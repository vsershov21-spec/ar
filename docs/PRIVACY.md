# Безопасность карты и данные

## Что видит ребёнок
- Онбординг, шаг 2 «Карта — только твоя»: никому не давать и не показывать, только маме или папе; цифры на карте коту не нужны.
- Под кнопкой на каждом шаге: «Номер, срок и код карты не считываются и не сохраняются» + ссылка «Условия».
- Лист «Условия и безопасность» (src/ui/ui.ts, `.terms`) — черновик текста для оферты/согласия, помечен «Черновик для согласования с юристами».

## Что делает прототип сейчас
- Детектор карты (src/tracker/card/) работает с уменьшенным кадром 320 px: края, углы, поток по текстуре стола. Распознавания текста (OCR), чтения номера/имени/срока/CVC нет.
- «Это банковская карта Сбера?» (src/tracker/card/verify.ts): смотрим только на **форму и знаки** — пропорции и скруглённые углы, чип (металлический прямоугольник), знак Сбера (кольцо с галочкой — по форме), логотип платёжной системы в углу, магнитную полосу на обороте. Для этого берём фрагмент кадра вокруг карты в разрешении камеры (до 420 px по стороне) и выпрямляем его в картинку 200 × 126. Номер, имя, срок и CVC **не читаются**: нет OCR, нет распознавания символов, зона номера в признаках не участвует (только общее «на карте есть рисунок»).
- Кадры и фрагменты не сохраняются и не отправляются: всё в Web Worker на устройстве, буферы перезаписываются следующим кадром. В ?debug видна только строка чисел-признаков, не картинка.
- Тестовые кадры в репозитории (tests/fixtures/cards) — с размытой зоной номера, имени и срока.
- Голос: Vosk в браузере, звук на сервер не уходит.

## Пункты для оферты (на согласование)
1. Изображение карты используется только для определения её положения на поверхности и того, что это карта Сбера (по форме, чипу и знаку банка, без чтения реквизитов).
2. Реквизиты карты (номер, имя держателя, срок, CVC) не распознаются, не сохраняются, не передаются.
3. Видео и звук обрабатываются на устройстве и не записываются.
4. Доступ к камере и микрофону — по разрешению, отзывается в настройках.
5. Прототип не даёт доступа к счёту, покупкам и переводам.

## Прогресс на сервере (server/progress, src/progress)
- **Признак устройства** — случайный UUID, созданный при первом запуске (localStorage `ar.device` + cookie `ar_device`).
  Фингерпринтинга нет: модель телефона, экран, шрифты, IP для id не используются. Очистили данные сайта — новое устройство.
  Короткий код (первые 6 символов id) — только для сброса продактом.
- **Что уходит на сервер**: ключи памяти `sber-ar-cat:*` (знакомство, выбранный кот, число визитов,
  время последнего визита, настройки сцены), `ar.catalog.tried` (какие действия пробовал), `ar.micMode`, `ar.focal.v1`
  (калибровка камеры); история сессий — начало/конец, кот, смены фазы и кота (без текста речи, без реплик, без кадров).
- **Имя ребёнка на сервер не уходит никогда** — во всех редакциях (mvp, lab, pilot), без флагов и исключений. Оно живёт
  только в localStorage телефона. Клиент (`src/progress/sync.ts` `stripName`) вырезает из каждого ключа прогресса все поля,
  похожие на имя (`name`, `nameKnown`, `childName`, «имя»… — и во вложенных объектах), перед любой отправкой (PUT, sendBeacon);
  сервер (`server/progress/store.mjs` `stripName`) вырезает их ещё раз при записи и не отдаёт при чтении — на случай старого
  клиента в кэше браузера. Записи, сохранённые до 20.11.2026, чистит `scripts/deploy/progress-purge-names.sh` (бэкап → удаление
  `name` → проверка). Тест: `tests/progress/sync.test.ts` — ни один исходящий запрос не содержит имени.
  Без сервера совсем: `?progress=0` или `VITE_PROGRESS=0`.
- Сервер: доступ только с нашего домена (CORS), без логов тел запросов, хранение 90 дней с последнего изменения,
  сброс — `?reset=1`, кнопка на `/test`, админ-страница по коду; `DELETE …?all=1` стирает и историю сессий.
- Для оферты: «Прогресс игры (выбранный персонаж, открытые действия; имя ребёнка остаётся только на телефоне) хранится на сервере банка по случайному
  идентификатору устройства до 90 дней; родитель может стереть его кнопкой в настройках». Перед пилотом с реальными
  детьми — согласовать с юристами (152-ФЗ: id устройства; имени на сервере нет).
