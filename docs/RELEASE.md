# Выпуск пилота: ветка `release` → /mvp

С 26.11 к детям (https://ar.vershov.com/mvp, редакция **pilot**) попадает только то, что лежит в ветке **`release`**.
`main` по-прежнему автодеплоится через 2–5 минут, но только в корень (`/`, MVP), `/lab` и `/test`.

| адрес | редакция | откуда | когда обновляется |
|---|---|---|---|
| `/mvp/` | pilot (дети, QR) | ветка `release` | после fast-forward `release` (2–15 мин) |
| `/lab/` | lab | `main` | каждый push в `main` (2–5 мин) |
| `/`, `/test/` | mvp, тестовые флоу | `main` | каждый push в `main` |

## Как выпустить

1. В `main` — то, что хотим показать детям (как обычно: tsc + vitest + build зелёные до push).
2. Продакт смотрит `/lab/` на iPhone по чек-листу ниже (lab ≈ pilot + экспериментальные функции; пилотные флаги —
   `docs/EDITIONS.md`). Если нужен ровно pilot-вид — `npm run e2e:pilot` локально собирает именно его.
3. Выпуск — одной командой (нужен push в GitHub):

   ```bash
   npm run release:promote                 # последний origin/main
   npm run release:promote -- 1a2b3c4      # конкретный коммит из истории main
   npm run release:promote -- --dry        # только проверки, без push
   ```

   `scripts/release/promote-release.sh`: коммит должен быть в истории `origin/main`, а текущий `release` — его предком
   (только fast-forward, без `--force`); в отдельном worktree на этом коммите — **полные проверки**: `tsc` → весь
   `vitest` последовательно → `npm run build` → `npm run e2e:pilot`. Красное — стоп, `release` не трогается.
   Зелёное — `git push origin <коммит>:refs/heads/release`.
4. Сервер (ar-update, раз в 2 мин) видит новый коммит `release` и собирает /mvp. Первая сборка нового коммита
   release — `npm ci` + сборка ~5–15 мин; дальше push в `main` /mvp не пересобирает (берёт готовое из кэша).
5. Проверка, что вышло (из песочницы сайт не виден — задачей ar-auto):

   ```bash
   node scripts/automation/enqueue.mjs script scripts/deploy/release-check.sh --timeout 40 -- release=1a2b3c4
   # коммит queue.json → push main → через 5–30 мин:
   node scripts/automation/enqueue.mjs result <id>
   ```

   `release-check.sh` ждёт, пока в HTML /mvp появится метка `<meta name="ar-build" content="1a2b3c4 pilot">`, и
   сверяет: /mvp — коммит `release`, /lab и корень — коммит `main`, `main.js` обеих страниц отвечает 200.
   Метку видно и в браузере: исходный код страницы → `ar-build`.
6. Продакт проходит чек-лист на iPhone уже на `/mvp/`.

**Откат пилота** — `release` только догоняет `main`, поэтому откат = выпуск: `git revert` в `main` → проверки →
`npm run release:promote`. Срочно (без пересборки) — переключить симлинк релиза на сервере (`docs/DEPLOY.md`
«Логи и откат»; имена релизов `<main>-r<release>`).

**Hotfix только для пилота** — не коммитить в `release` напрямую: исправление в `main`, затем выпуск. Если `main` уже
ушёл далеко и выпускать его целиком нельзя — ветка от `release`, исправление, PR в `main`; после влития
`promote-release` откажет (не fast-forward) — тогда решение за владельцем (`git push --force` в `release` — вручную,
осознанно).

## Как устроено на сервере

`/usr/local/bin/ar-update.sh` ← `server/ar-update/ar-update.sh` (ставит `scripts/deploy/release-setup.sh` задачей
ar-auto: бэкап прежнего скрипта, `bash -n`, пересборка, проверка меток /mvp и /lab, при ошибке — откат на прежний
скрипт и пересборка им). Сервис `ar-update` (oneshot, `vershov-commander`, таймер 2 мин) — без изменений.

1. `main` → `/srv/ar/repo` → `npm ci && npm run build` (три редакции, как раньше). `main` не менялся (сменился только
   `release`) — корень и /lab копируются из текущего релиза, без пересборки.
2. `release` → своя рабочая копия `/srv/ar/repo-release` → `npm ci` → `AR_EDITIONS=mvp,pilot npm run build` (кэш
   сжатых моделей общий с main) → готовый `dist` в кэш `/srv/ar/release-dist/<sha>` (3 последних).
3. Релиз `/srv/ar/releases/<main>-r<release>`: `dist` main, `mvp/` заменяется на `mvp/` из release, хэшированные файлы
   сборки release, которых нет в main (`models/opt/<модель>.<хэш>.glb`, пакеты движений, чанки), докладываются в
   корень без перезаписи (`cp -an`). Атомарное переключение `current`, хранятся 5 релизов.
4. Общие ассеты /mvp — из корня, то есть из `main`: модели без хэша, звуки, видео, мишени, Vosk и **озвучка**
   (`voice/el/manifest.json`, файлы `/srv/ar-extra/voice-el`). Новые записи ElevenLabs доходят до /mvp с ближайшей
   пересборкой main; реплик, которых нет в коде release, /mvp не просит. Если `main` переименует/удалит
   нехэшированный файл, который нужен коду release, — /mvp его не найдёт: такие изменения выпускать вместе.
5. Сборка release упала — /mvp остаётся прежним (дети не видят ни main, ни сломанную сборку), sha помечается
   `/srv/ar/release-dist/<sha>.failed`, повторов каждые 2 мин нет; новый коммит release — новая попытка. В
   `/srv/ar/update.log` — «ВНИМАНИЕ: release … не собрался».
6. Ветки `release` нет — всё как до 26.11 (/mvp из main).

Тест логики — `tests/arUpdate.test.ts` (локальный bare-репо вместо GitHub, фиктивная сборка).

## Чек-лист продакта на iPhone (перед выпуском — на /lab, после — на /mvp)

Safari, звук включён, детская карта под рукой. Новая сессия: `?fresh` в адресе (или «Очистить историю» в Safari).

1. **Вход и яйцо.** QR / адрес открывается без ошибок; заставка: из щели в карте моргают глаза, карта качается
   тремя сериями; «Узнать, кто там» → вспышка, сразу окно разрешения камеры.
2. **Карта.** Камера на карту: поиск находит её за пару секунд, контур прилипает; пробуждение — карта подпрыгивает
   3 раза со стуком, столб света, ПУФ — кот выпрыгивает.
3. **Знакомство и выбор кота.** «Как тебя зовут?» → имя или «Пропустить» → кот **голосом** «Выбери, кто будет с
   тобой!» и лист «Выбери своего кота» с тремя карточками.
4. **Хулиган.** Выбрать: вспышка, выскакивает из карты, катается **на скейте** (доска под лапами), знакомится своим голосом.
5. **Добряк.** «Другой кот» → лист «Позвать другого кота» (кот говорит «Кого позовём? Выбирай!») → Добряк: **какао**
   у груди, тёплый голос. Раньше чем через 3 мин — «Чуть позже!» и таймер на кнопке.
6. **Блёстка.** Третья смена: **зеркальце**, женский род в репликах («я рада»).
7. **Голос и микрофон.** Кнопка микрофона: разрешение спрашивается один раз; «давай другого» — лист выбора,
   «хочу Добряка» — сразу он; кот задремал — «просыпайся» будит.
8. **Меню.** Угостить, дай лапу, танец, сальто, загадка, раскраска карты — без «погладь / пощекочи / обними».
9. **Дом.** «Мир кота»: кот уходит в дом, комнаты листаются, «На карту» — возвращается в карту.
10. **Кровать.** В спальне — «Уложить спать»: одеяло, Zzz; «Разбудить» / шторка — потягивается и спрыгивает.
11. **Самокат.** Значок «Самокат?» → кот голосом про вкусняшки, 6 продуктов летят в корзину → лист «Перекус от
    <кота>» → «Отправить маме на оплату» → «Покажи этот экран маме…» → «Готово».
12. **СберKids и звук.** Значок «СберKids?» → копилка с монетками, экскурс 3 шага («Дальше» обрывает прежнюю фразу и
    говорит новую) → «Войти в СберKids» открывает СберKids. Все фразы — голосом, без робота; звук не пропадает после
    сворачивания Safari и возврата; громкость кнопками меняется; переключатель «бесшумно» — отметить, слышно ли кота.
