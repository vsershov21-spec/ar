# Редакции: MVP, Lab и Пилот

Три версии прототипа из **одного репозитория и одной ветки `main`**, с общим реестром моделей, озвучки и контента:

| Адрес | Редакция | Что в ней |
|---|---|---|
| https://ar.vershov.com | **mvp** — «вылизанный MVP» | только стабильные, проверенные функции |
| https://ar.vershov.com/lab | **lab** — «полная» | всё новое и экспериментальное; новые функции сначала живут здесь |
| https://ar.vershov.com/mvp | **pilot** — «пилот с детьми» | срез по документу продакта «СберКот AR — конструкция MVP для пилота»: урезанный каталог, 2 игры, белый список эффектов, кровать, аналитика воронки (раздел «Пилот» ниже) |

Новая функция попадает в MVP **флагом** после проверки на iPhone: `mvp: true` в таблице `FEATURES`
(`src/config/edition.ts`) и «да» в колонке «проверено на iPhone» ниже. Больше нигде ничего менять не нужно.

### Как функция проверяется в коде

```ts
import { feature } from '../config/edition';
if (feature('stickers.pack')) { /* новое */ } else { /* как в MVP */ }
```

Проверка — **в точке входа** функции (создание контроллера, пункт каталога, диалог), без перекраивания кода.
Параметры адреса проверяются централизованно: `PARAMS` в `edition.ts` (параметр → функция). В редакции, где функция
выключена, `guardUrl()` (первый импорт `main.ts`, `src/config/boot.ts`) вырезает параметр из адреса до старта
приложения — модули, которые сами читают `location.search` (cardTracker, flows, app.ts), его просто не видят.
Ссылка со страницы /test несёт метку `?from=test` (или referrer `/test/`): с ней в MVP остаются `?flow`, `?nocard` и `?desktop`
(кроме флоу выключенных игр). `?debug` работает в обеих редакциях.

Новая функция: строка в `FEATURES` (`mvp: false, lab: true`) + строка в этой таблице + `feature('…')` в точке входа.
Если у функции уже есть выключатель в адресе — достаточно `OFF_SWITCH` (как `awake` → `?awake=0`).

## Сборка

`npm run build` (его вызывает сервис `ar-update`, скрипт сервиса не меняется) =
`pull-server-voice → scripts/build/editions.mjs → attach-extra`. `editions.mjs` в одном процессе собирает подряд:

| | mvp | lab | pilot |
|---|---|---|---|
| куда | `dist/` | `dist/lab/` | `dist/mvp/` |
| base (html/js/css) | как раньше (`BASE_PATH ?? './'`) | `/lab/` | `/mvp/` |
| страницы | `index.html`, `test/**/index.html` | только `index.html` (/test общий) | только `index.html` |
| `public/` (модели, звуки, видео, мишени, наклейки, озвучка ElevenLabs) | копируется в `dist/` | **не копируется** — из корня | из корня |
| сжатые модели `models/opt/*` (model-opt) | кладутся в `dist/models/opt` | только карта путей, файлы те же (кэш model-opt и память процесса — общие) | так же |
| озвучка Piper и Vosk-модель (attach-extra, `/srv/ar-extra`) | `dist/voice`, `dist/models/vosk-*` | те же, из корня | из корня |
| `VITE_ASSET_BASE` (`src/core/util.ts asset()`) | = base | `/` | `/` |
| префикс localStorage / cookie | — / `ar_device` | `lab:` / `lab_ar_device` | `pilot:` / `pilot_ar_device` |
| прогресс на сервере, поле `edition` | `mvp` | `lab` | `pilot` |

Тяжёлые ассеты лежат один раз; в `dist/lab` — только код (~11 МБ js/wasm, включая vosk-browser и декодеры).
Время сборки (локально, тёплый кэш model-opt): было ~6,5 с (одна сборка), стало ~7,3 с (mvp ~2,9 + lab ~2,5 с).
На сервере основное время — `npm ci` и первая перекодировка моделей; вторая сборка моделей не кодирует.

- Одна редакция: `AR_EDITIONS=mvp npm run build` (или `lab`, `pilot`, `mvp,pilot`). Подпапку задаёт `AR_SUB_DIR` (`vite.config.ts`).
- Просто `vite build` (CI-шаг QA-стенда) — одна сборка в `dist/`, редакция по `VITE_EDITION`, без неё — **lab**
  (как было до редакций: всё включено). `npm run dev` — тоже lab.
- QA-стенд по редакциям: `VITE_EDITION=mvp npm run qa -- --only first`, `VITE_EDITION=lab npm run qa -- --only first`
  (стенд собирает сам, в корень, без префиксов хранилища — отдельный origin).
- Проверка двух редакций после сборки: `npm run check:editions` — структура `dist/` и `dist/lab/`, нет копий ассетов
  в lab, сжатые модели из карты lab существуют в корне; headless Chrome на локальном сервере «как Caddy»: в mvp
  параметры выключенных функций вырезаны и новых мини-игр нет, lab — плашка LAB, все ассеты из корня, без 404,
  свои ключи localStorage и cookie, SPA-фолбэк `/lab/*`.

## Хранилище

lab и mvp живут на одном домене, поэтому в lab все ключи localStorage — с префиксом `lab:` (память кота
`lab:sber-ar-cat:v1`, id устройства `lab:ar.device`, каталог, калибровка, наклейки…), cookie id устройства —
`lab_ar_device`. Модули пишут в `localStorage` как раньше: `installStorageNamespace()` (`edition.ts`) подменяет
`getItem/setItem/removeItem/key/length/clear` только для `localStorage` (сборка lab задаёт `VITE_STORAGE_PREFIX=lab:`).
Эксперименты в lab не портят MVP; сброс в lab — `https://ar.vershov.com/lab/?reset=1` или `?fresh`.

Сервер прогресса: у lab свой id устройства (свой код на /test/admin) и поле `edition` (`mvp`|`lab`) — клиент шлёт его
в записи прогресса и в начале сессии, сервер хранит в документе, показывает в GET, в истории сессий и в админ-поиске
по коду. Старый сервис (без правки) поле просто игнорирует — обновить `/opt/ar-progress/server.mjs` (docs/DEPLOY.md).

## Пилот: https://ar.vershov.com/mvp (редакция `pilot`)
